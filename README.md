# Agent Start From Frontend

从 Web 前端工程师出发，系统学习 AI / LLM 与 Agent 工程，通过连续迭代的项目积累可验证的工程能力。

## 总体目标

逐步具备独立设计、开发、测试、部署和维护 AI / Agent 应用的能力。重点不只是调用模型或使用框架，而是理解系统机制、验证结果、处理失败、控制权限与成本，并交付可复现的项目。

## 规划原则

- **主线围绕工程成果，而非语言或框架清单。** 每个阶段都产出能运行、能测试、能解释的结果。
- **先发挥 TypeScript 优势。** 用熟悉的语言学习模型 API、状态管理和 Agent 核心机制，避免一开始同时承担语言切换和 AI 概念两种负担。
- **Python 按需补齐，不设强制独立阶段。** Python 专项投入的初始预算约为总学习投入的 10%–15%，不是硬性配额；在 RAG、数据处理或框架确有需要时集中补齐。
- **从基础开始讲，不假设数学或后端基础扎实。** 使用小例子与代码解释新概念；数学只学当前理解所必需的部分，不要求先补完整套数学课程。
- **评估贯穿全程。** 从早期测试结构化输出开始，到 RAG 检索评估、Agent 任务成功率和生产观测，不能只以 Demo 能运行作为完成标准。
- **从一个连续项目演进。** 以售后支持场景为主线，逐步加入模型 API、知识库、工具调用、MCP 和生产保障；尽量复用前期成果。
- **云端优先、轻量开发。** 不把本地运行大型模型作为前置条件。

## 核心学习路线

| 阶段 | 主题 | 主要成果 |
|---|---|---|
| 1 | AI / LLM 基础与结构化交互 | 可校验、有状态的多轮售后交互原型 |
| 2 | 模型 API 与 TypeScript 后端 | 有流式输出、错误处理和测试的 AI 应用 |
| 3 | RAG、检索与评估 | 能引用证据、处理无答案并评估质量的知识库 |
| 4 | Tool Calling 与 Agent | 能调用受控工具、管理状态并完成多步骤任务的售后 Agent |
| 5 | MCP（重要可选扩展） | 能理解 MCP 取舍并接入已有 Server；深入开发按项目需要决定 |
| 6 | 生产级 Agent 工程 | 可评估、可观测、可部署、安全且可维护的项目 |

Python 是贯穿主线的**按需能力模块**，不是必须先完成的阶段。优先学习语法、函数、列表/字典、类型标注、异常、虚拟环境、依赖管理、异步基础和测试；遇到 Python 生态工具时再补 Pydantic、FastAPI 等。暂不系统学习模型训练、深度学习数学或数据科学全套内容。详见 [Python 按需补充模块](modules/python-on-demand.md)。

## 教学方式

默认采用“**代码示例 → 解释关键概念 → 分析工程问题 → 简短练习（必要时）**”。

- 利用用户已有的 Web 前端和 TypeScript 经验引入新概念。
- 代码用于帮助理解，不要求每节课都先写完整项目；也避免长篇纯概念讲解。
- 一次聚焦少量新概念，使用最小而有意义的例子，减少重复解释和装饰性排版。
- 对前端之外的后端、网络、数据库、命令行和部署概念，首次出现时仍要解释清楚。
- 如果暂时没理解，换一种讲法或例子，再继续推进。

## 学习节奏原则

不规定每次学习必须投入固定时长。学习单元的大小、连续投入时间和拆分方式由内容难度、任务完整性和学习效果决定。需要连续思考或调试的任务优先保障连贯性；短知识点在达到目标后即可结束。

进度按实际完成的学习单元和阶段验收结果记录，不按日历天数推进。中断后从上次实际进度继续，不自动跳过内容，也不为了赶进度牺牲理解与验证。

## 工程与工具原则

- 优先使用云端模型/API，不把本地运行大型模型作为前置条件。
- 先理解核心机制，再按需求选择 SDK 或框架。
- 模型输出视为需要校验的数据；可信业务事实与最终执行由后端负责。
- 对缺失信息、异常输出、工具失败和高风险操作设计明确的控制流程。
- 从早期就积累测试用例；RAG、Agent 和生产项目逐步增加质量评估、日志与追踪。
- 优先将一个项目持续迭代为作品集，强调工程深度、可解释性和可复现性。

## 外部路线参考与吸收原则

本路线参考过开源 AI 工程路线和课程的组织方式，吸收以下实践：以交付物和阶段验收推进；把评估、可观测性、安全和系统设计纳入主线；Agent 学习包含工具调用、状态、停止条件、人工确认和最终测试。不会直接照搬大型路线中的全部主题，也不会把多框架学习、模型训练或 Kubernetes 等内容设为当前必修。
