# 阶段四：Tool Calling 与 Agent

> 目标：从一次性生成回答，进阶到能够调用受控工具、维护任务状态、观察执行结果并完成多步骤任务的系统。

## 学习范围

1. Tool Calling 的请求、工具选择、参数和返回流程
2. 工具 Schema、参数校验与错误返回
3. 模型输出、工具返回事实和后端执行结果的区别
4. 手动实现简化的 Agent 执行循环
5. 任务分解、执行、观察、验证和继续/停止判断
6. 对话状态、任务状态与记忆的区别
7. 工具失败、超时、重试、循环限制和停止条件
8. 幂等性与重复执行风险的基本概念
9. 最小权限、人工确认和高风险操作边界
10. Agent 框架能解决什么问题，以及引入框架的代价
11. 基础运行记录：为什么调用工具、输入是什么、结果如何

## 实践项目：售后支持 Agent

在前面的售后交互原型和知识库基础上逐步扩展。Agent 可以：
- 理解用户问题并追问缺失信息。
- 查询订单或售后政策等受控工具。
- 根据工具返回的可信数据判断下一步。
- 在换货条件不满足时解释可选方案。
- 在退款等有副作用的操作前进行业务校验，并按风险要求请求人工确认。
- 记录任务状态、工具调用和最终结果。

不要求一开始接入真实支付或订单系统；可以用带固定测试数据的模拟服务练习权限、校验和失败流程。

## 阶段验收标准

- 能独立定义至少两个工具，并为输入输出设计 Schema。
- 能解释并实现一个基本的 Agent 循环。
- 能管理缺失信息、任务状态、停止条件和失败路径。
- 能防止无效参数、无限循环和不必要的重复执行。
- 能区分模型建议、工具返回的数据和后端最终执行结果。
- 能判断哪些操作可以自动执行、哪些需要人工确认。
- 能通过测试案例和运行日志解释任务为何成功或失败。

## 学习顺序

先手动实现核心机制，再按具体问题引入框架。先做一个边界清晰的单 Agent，不把多 Agent 协作作为前置要求。会使用框架不等于理解 Agent 原理。
