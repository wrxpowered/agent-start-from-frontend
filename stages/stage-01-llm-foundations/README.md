# 阶段一：AI / LLM 基础与结构化交互

## 学习优先级

- **必修：** Token 与上下文、消息角色、Prompt、结构化输出、Schema、缺失信息追问、状态转换、模型与后端职责边界。
- **了解即可：** 生成参数的基本作用、模型能力边界和常见失误。
- **后续再学：** 模型训练、复杂数学推导、微调细节。无需先完成完整数学课程。

> **阶段状态：进行中。单元 1 的概念学习已完成；阶段整体尚未验收。**

## 本阶段目标

理解模型交互的基本机制，并能设计可校验、有明确状态和业务边界的交互流程。模型能生成看似合理的文字，但应用不能直接把任意生成内容当成可信事实或可执行指令。

## 学习方式

采用“代码示例 → 解释关键概念 → 分析工程问题 → 简短练习（必要时）”。利用 TypeScript 和前端经验降低理解成本；避免冗长的纯概念讲解，也不要求每节课都从零编写完整项目。

## 学习范围

1. **LLM 基础：** Token 与用量、上下文窗口、生成特点与不确定性、消息角色、Prompt、常见生成参数。
2. **结构化输出：** JSON、Schema、字段类型、枚举、必填/可空字段、运行时校验、校验失败后的处理。
3. **交互流程：** 意图识别、信息提取、缺失字段与澄清问题、多轮上下文、状态转换、停止条件和兜底路径。
4. **系统边界：** 模型推断与用户明确提供的信息、模型输出与后端可信事实、后端权限和业务校验、最终执行及异常处理。

## 实践项目：售后支持交互原型

以“耳机右侧没有声音，优先换货，换不了则退款”为案例，逐步构建多轮交互流程。

系统应能够提取商品、问题和用户诉求；明确表示未知字段；追问缺失信息；通过后端校验订单与业务资格；区分模型建议、校验结果和执行结果；为无效输出、业务不满足和系统故障设计不同处理路径。

## 建议交付物

- 结构化输出 Schema。
- 状态转换说明。
- 至少 5 个测试场景，覆盖正常输入、缺失字段、模糊输入、无效模型输出和业务校验失败。
- 对模型、编排层与后端职责的简短说明。

## 阶段验收标准

- 能解释 Token、上下文窗口和 Prompt 的作用与边界。
- 能设计类型明确、可校验的结构化输出。
- 能识别必需字段缺失并设计追问。
- 能描述多轮交互的状态转换和停止条件。
- 能区分模型推断、用户输入、后端事实与业务执行结果。
- 能为异常输入、无效输出和业务失败设计处理路径。
