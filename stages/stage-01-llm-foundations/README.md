# 阶段一：AI / LLM 基础与结构化交互

## 学习优先级

- **必修：** Token 与上下文的基本概念、消息角色、结构化输出、Schema、必填/可空字段、缺失信息追问、状态转换、模型与后端职责边界。
- **了解即可：** 生成参数的基本作用、模型能力边界和常见失误。
- **后续再学：** 模型训练、复杂数学推导、微调细节。无需先完成完整数学课程。


> 状态：进行中  
> 本阶段的目标是理解模型交互的基本机制，并能设计可校验、有明确状态和业务边界的交互流程。

## 本阶段要解决的问题

模型能生成看起来合理的文字，但应用不能直接把任意生成内容当成可信事实或可执行指令。本阶段学习如何约束模型输出、识别信息缺口，并把模型放进可靠的交互流程。

## 学习方式与基础要求

本阶段不要求先补数学课程，也不要求预先掌握后端开发。遇到新术语时，先用生活化例子解释其作用，再介绍准确概念。需要少量数学直觉时，会用简单数字举例，不要求复杂推导。

## 学习范围

1. **LLM 基础**
   - Token 与 Token 用量
   - 上下文窗口与上下文组织
   - 模型生成的基本特点、能力边界与不确定性
   - System Prompt、用户消息和对话上下文
   - 温度等生成参数的基本作用
2. **结构化输出**
   - JSON 输出与常见格式错误
   - Schema、字段类型、枚举、必填和可空字段
   - 输出解析、校验失败与修复/重试策略
3. **交互流程**
   - 意图识别与信息提取
   - 缺失字段识别和澄清问题
   - 多轮对话上下文与会话状态
   - 状态转换、停止条件和兜底路径
4. **系统职责边界**
   - 模型推断结果与用户明确提供的信息
   - 模型输出与后端可信业务事实
   - 后端校验、权限判断和最终业务执行
   - 无效输出、歧义输入与异常处理

## 实践项目：售后支持交互原型

以“耳机右侧没有声音，优先换货，换不了则退款”为案例，设计一个多轮交互流程。

系统至少需要：
- 提取商品、问题、主要诉求和备用诉求。
- 对未知字段使用明确的缺失状态，不能自行猜测订单号或金额。
- 根据当前状态决定下一步需要向用户追问什么。
- 通过后端校验订单、资格、库存和金额等可信业务信息。
- 将模型建议、校验结果和实际执行结果分开表示。
- 在信息不足、输出不合法或业务不满足时给出明确的兜底路径。

## 建议的交付物

- 一份结构化输出 Schema。
- 一张或一段可读的状态转换说明。
- 至少 5 个测试场景，覆盖正常输入、缺失字段、模糊输入、无效模型输出和业务校验失败。
- 一份简短说明，解释模型、Agent 编排层和后端各自负责什么。

## 阶段验收标准

- 能用自己的话解释 Token、上下文窗口和 Prompt 的作用及边界。
- 能为场景设计类型明确、可校验的结构化输出。
- 能识别必填字段缺失，并设计有针对性的追问。
- 能描述多轮交互中的状态转换和停止条件。
- 能区分模型推断、用户输入、后端事实与业务执行结果。
- 能为异常输入、无效输出和业务失败设计处理路径。

达到以上标准后，再进入模型 API 与 TypeScript 后端。无需在本阶段深入复杂数学或训练模型。

## 本阶段暂不深入

- 大规模模型训练和微调
- 复杂神经网络数学推导
- 向量数据库与完整 RAG 实现
- Agent 框架的系统性学习
- 生产环境的完整监控与部署体系
