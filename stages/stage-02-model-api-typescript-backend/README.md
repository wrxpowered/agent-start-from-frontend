# 阶段二：模型 API 与 TypeScript 后端

## 学习优先级

- **必修：** HTTP/请求响应、Node.js 服务端、模型 API、密钥保护、输入输出校验、超时与错误处理、基本测试和可复现部署。
- **了解即可：** 流式响应、数据库与会话持久化的基本原理；在项目中逐步实践。
- **后续再学：** 复杂分布式架构、全面云平台运维体系和与当前项目无关的基础设施。


> 目标：利用已有的 Web 前端基础，构建端到端的 AI 应用，建立后端服务、模型调用和工程化处理的完整经验。

## 为什么先用 TypeScript

先使用熟悉的 TypeScript / Node.js，可以把学习注意力集中在模型 API 和 AI 应用工程上。Python 作为按需能力模块，在 RAG、数据处理或框架确有需要时再补齐；两者不是互斥路线。

## 学习范围

1. HTTP、REST API、请求与响应
2. Node.js 服务端基础和项目结构
3. 模型 API、消息组织和多轮对话
4. 流式响应与 SSE
5. 超时、重试、错误分类、取消请求和限流基础
6. JSON Schema / Zod 等输入输出校验
7. 环境变量、密钥管理与服务端安全边界
8. 数据库基础、会话持久化
9. 单元测试、集成测试与部署
10. 模型供应商和 SDK 的可替换性

## 实践项目：完整 AI 对话应用

交付一个具有前端界面和服务端 API 的应用：
- 前端可以发送消息并展示流式输出。
- 服务端负责调用模型，密钥不暴露到浏览器。
- 支持多轮上下文和必要的会话持久化。
- 对超时、网络错误、限流和无效输出有明确处理。
- 关键输入与输出有类型或 Schema 校验。
- 有基本测试和可复现的部署说明。

## 阶段验收标准

- 能独立完成前端到后端再到模型 API 的完整调用链。
- 能解释流式响应和普通请求的区别。
- 能正确处理常见错误、超时和重试边界，避免无限重试。
- 能安全管理 API 密钥。
- 能通过测试验证关键行为，并部署一个可运行版本。

## 暂不要求

- 复杂分布式架构
- 多 Agent 协作
- 全面的生产监控平台
- 同时学习多个重叠的前端 AI 框架

## 与后续阶段的关系

本阶段建立可运行的 AI 应用底座；下一阶段进入 RAG。若项目所选工具需要 Python，就围绕实际任务补齐必要语言与工程基础，不要求先完成独立的 Python 课程。
