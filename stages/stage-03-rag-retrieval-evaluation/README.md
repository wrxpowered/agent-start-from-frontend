# 阶段三：RAG、检索与评估

> 目标：构建能基于外部资料回答问题、提供可核查证据，并能用固定测试集判断检索和回答质量的知识库应用。

## 为什么在这里学习 RAG

完成模型 API 应用后，下一步是让模型利用业务文档，而不是只依赖模型已有知识。RAG 也会引入文档处理、检索质量和证据引用等问题，是后续 Agent 获取可信上下文的重要基础。

## 学习范围

1. RAG 的端到端流程与适用边界
2. 文档解析、清洗、切分和元数据
3. Embedding 的直观理解及其用途
4. 向量检索、Top-K 和向量数据库的基本作用
5. 关键词检索与混合检索的差异
6. 上下文组装、来源引用和无答案策略
7. 检索失败与生成失败的区别
8. 使用固定问题集进行基础评估，例如 Recall@K 和答案依据检查
9. 按实际问题了解重排序、查询改写等进阶手段

## Python 在本阶段的定位

不要因为进入 RAG 就先暂停项目、系统学完整门 Python。先判断所选工具和实现是否真的需要 Python：
- 如果使用的库、数据处理流程或框架主要面向 Python，就在项目中补齐所需语法与工程基础。
- 如果 TypeScript 已能满足当前目标，可以先用 TypeScript 实现最小 RAG，再根据后续生态需求补 Python。
- 不论语言如何选择，都必须理解切分、检索、证据、无答案处理和评估这些核心概念。

## 实践项目：带来源引用的知识库问答

以售后政策、产品说明或一组工程文档作为知识源。系统应支持：
- 导入和处理一组文档。
- 根据用户问题检索相关片段。
- 将检索证据交给模型生成回答。
- 在回答中提供可核查的来源。
- 证据不足时明确说明无法确定，而不是编造。
- 用一组固定问题检查检索与回答质量。

## 阶段验收标准

- 能解释文档切分、Embedding 和检索分别解决什么问题。
- 能识别检索失败与生成失败的差别。
- 能用固定测试问题检查检索效果，而不是只凭主观感受。
- 能追溯回答引用的来源。
- 能测试无答案、冲突资料、低相关结果和文档更新等边界情况。
- 能说明当前方案的局限，以及何时值得引入混合检索或重排序。

## 学习边界

先完成一个简单、可评估的 RAG。不要一开始同时学习多个向量数据库、复杂 Agentic RAG、GraphRAG 或所有重排序方法。更复杂的方案应由测试结果和实际需求驱动。
