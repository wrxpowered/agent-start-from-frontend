# 阶段六：生产级 Agent 工程

> 目标：把前面完成的 AI 对话、RAG 和 Agent 原型逐步改造成可评估、可观测、可控制风险、可部署和可维护的工程产品。

## 学习范围

1. 评估集、回归测试和任务成功率
2. 结构化输出、检索质量、工具选择和最终任务结果的分层评估
3. 日志、Trace、运行过程回放和故障定位
4. Token、成本、延迟和性能优化
5. Prompt Injection 与不可信内容处理
6. 身份认证、工具权限、速率限制和密钥管理
7. 敏感信息保护与数据最小化
8. 超时、取消、异步任务和必要的队列基础
9. 幂等性、重复执行防护、中断与恢复
10. CI/CD、部署、环境配置和版本管理
11. 监控、告警和常见故障排查
12. 架构文档、限制说明、演示和作品集整理

## 实践项目：生产化改造

选择前面持续演进的售后 Agent 或知识库应用，针对可靠性、安全性、评估和可维护性进行一轮系统改造。

项目至少应具备：
- 可重复运行的测试和评估集。
- 可追踪的关键执行过程。
- 明确的工具权限、业务校验与人工确认边界。
- 对失败、超时和重复执行的处理。
- 对成本与延迟的基本记录。
- 可复现的部署流程和清晰的项目文档。
- 对已知限制、失败案例和后续改进方向的说明。

## 阶段验收标准

- 能通过测试或评估结果说明系统质量，而非只凭 Demo 展示。
- 能追踪关键步骤并定位常见失败。
- 能解释主要安全风险及对应控制措施。
- 能处理超时、重复执行和任务恢复等关键场景。
- 能部署系统，并让其他人按照文档复现运行。
- 能说明架构选择、已知限制、成本和延迟的权衡。

## 最终作品集

优先形成一个有深度、连续演进的主项目，并视进度整理为三个展示面：
1. AI 对话应用：模型接入、流式交互、错误处理与基本测试。
2. RAG 知识库：文档处理、检索、引用和质量评估。
3. Agent 工程产品：工具调用、状态管理、MCP、权限、安全、可观测性和部署。

这些不要求是三个完全独立的项目；允许在同一个业务系统上持续演进。优先交付一个完整、可部署、有评估报告的项目，而不是堆出多个未完成的 Demo。

## 当前不作为必修的内容

- 从零训练基础模型或深入模型微调
- 多 Agent 系统
- Kubernetes 和复杂分布式架构
- 同时掌握多个重叠的 Agent 框架
- 为了追求技术栈完整而学习与项目无关的工具
