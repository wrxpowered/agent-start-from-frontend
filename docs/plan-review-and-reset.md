# 学习计划复核与重启记录

## 复核后的总体目标

从已有 Web 前端工程能力出发，逐步掌握构建、测试、部署和维护 AI / Agent 应用所需的能力。目标是能解释关键机制、处理失败与边界情况，并交付可复现、可验证的工程项目，而不只是调用模型或熟悉某个框架。

## 复核后的路线

1. **AI / LLM 基础与结构化交互（必修）**：理解 Token、上下文、消息角色、结构化输出、Schema、信息缺口、状态与模型/后端职责边界。
2. **模型 API 与 TypeScript 后端（必修）**：建立 HTTP/请求响应、Node.js 服务端、模型 API、密钥保护、输入输出校验、错误处理和测试能力；基础流式响应/SSE 是交付物的一部分，因此调整为必修实践。
3. **RAG、检索与评估（当前主项目的核心能力）**：完成可评估的基础检索、证据引用和无答案策略；不将复杂 RAG 变体设为前置要求，也不声称 RAG 是所有 Agent 的普适前置。
4. **Tool Calling 与 Agent（必修核心）**：手动理解并实现基本执行循环、工具 Schema、状态、结果观察、停止条件、错误处理和权限边界。
5. **MCP（重要可选扩展）**：理解协议并按需求接入现有 Server；深入自建 Server 不作为进入生产工程的硬性门槛。
6. **生产级 Agent 工程（必修目标）**：系统化回归测试、评估、日志/追踪、安全、部署、故障定位、成本与延迟管理。

Python 继续作为按需能力模块，而非独立前置阶段；优先用 TypeScript 降低同时学习新语言和新 AI 概念的负担。是否增加 Python 深度由实际项目、工具生态和目标岗位要求决定。

## 本次发现并修正的问题

- **阶段二内部要求不一致**：项目交付物要求流式输出，但原优先级把流式响应列为“了解即可”。现已调整为必须具备基础 SSE/流式响应实践能力；数据库与会话持久化仍按项目需要逐步深入。
- **MCP 在作品集描述中容易被误读为必需项**：现已明确生产级 Agent 作品集以工具调用、状态管理、安全、可观测性和部署为核心；MCP 根据项目集成需要作为可选扩展。
- **旧进度可能让新计划继续沿用过去的完成状态**：现已将全局进度和阶段一笔记重置，并把旧笔记单独归档，明确不计入新计划。

## 保留的设计决定

- 不要求先完成完整数学课程、模型训练或本地大模型部署。
- 不同时学习多个重叠的 Agent 框架；先理解机制，再按需求选工具。
- 测试、评估和安全逐步贯穿各阶段，而不是全部推迟到最后。
- 尽量沿用一个连续的售后支持项目，逐步演进为可展示的工程成果。
- 学习单元按实际完成情况推进，不使用日历天数编号，也不规定僵化课时。

## 每个学习单元的执行与同步流程

1. 简要说明本单元在整体路线中的位置和目的。
2. 从问题和直觉开始讲解，再连接到术语、示例和代码。
3. 完成实践任务，并明确说明成功结果应是什么。
4. 用小测、测试场景或代码检查确认结果。
5. 总结本单元真正掌握的内容、尚未掌握的部分和下一步。
6. 及时更新 `PROGRESS.md`、当前阶段笔记；只有路线本身变化时才同步修改路线文档。

## 复核原则

路线不因新工具流行就频繁重构。只有当实际项目测试、目标岗位要求、阶段验收结果或重要生态变化证明有必要时，才调整顺序或深度；调整时记录原因，保留有用的历史材料。
