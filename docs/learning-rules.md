# 学习规则与工程原则

## 学习节奏与进度

- 不规定每次学习必须投入固定时长；按内容难度、连续性和学习效果安排。
- 需要连续思考、编码或调试的任务，优先保障完整性和思路连贯，不为了满足时长而强行中断。
- 短知识点在理解并完成必要验证后即可结束，不为了凑时长增加内容。
- 使用实际完成的学习单元追踪进度，不使用连续日历天数编号。
- 中断后从上次实际进度继续，不因错过日期而自动跳过内容。
- 未达到学习目标或阶段验收标准时，继续补充练习和验证，不因计划日期而提前推进。
- 每个学习单元按需包含：路线定位、概念讲解、实践任务、结果验证和总结；具体深度与时长由内容决定。
- 日常学习聚焦当前阶段。总体路线用于把握方向，不要求一次学习跨越多个阶段。

## 从基础讲起的教学原则

- 不假设用户具备扎实的数学、后端、数据库、网络、命令行或部署基础。
- 每个新概念先说明它要解决的问题，再给直观解释、具体例子，最后连接到术语和代码。
- 对前端开发者熟悉的概念可以类比，但必须解释类比的边界，不能只靠比喻代替准确解释。
- 数学先从直觉和小例子开始。只有确实有助于当前任务时才使用公式；出现公式时解释符号、用途和实际意义，不要求先修完整套数学。
- 对陌生的后端流程，按请求从哪里来、经过哪些步骤、结果返回哪里逐步说明。
- 代码示例从最小可运行版本开始，逐步增加复杂度；关键代码要解释为什么这样写，以及常见错误如何排查。
- 每个知识点标明优先级：当前必须掌握、理解大意即可、后续按需学习。
- 如果用户没理解，不直接跳过或一次性增加更多术语；换一种讲法，使用例子或小练习确认理解后再继续。

## 总体学习路线

AI / LLM 基础与结构化交互 → 模型 API 与 TypeScript 后端 → RAG、检索与评估 → Tool Calling 与 Agent → MCP → 生产级 Agent 工程。

Python 作为按需能力模块穿插在主线中，不作为必须先完成的独立阶段。初始预算约为总学习投入的 10%–15%，用于掌握 AI 应用开发需要的基础能力；这只是规划估算，不是硬性配额。遇到 Python 专属工具或框架时，按项目需要集中补齐。详见 [Python 按需补充模块](../modules/python-on-demand.md)。

## 项目与评估原则

- 尽量围绕连续的业务场景迭代项目，避免每个技术主题都另起一个无关 Demo。
- 每个阶段都有明确交付物和可检查的验收标准。
- 从早期就建立测试样例；结构化输出、检索和 Agent 都要检查边界情况。
- “可以运行”不是充分的完成标准；要能解释为什么成功、如何发现失败、如何控制风险。
- 先手动理解核心机制，再引入框架；避免同时学习多个功能重叠的框架。
- 云端模型/API 优先，不把本地运行大型模型作为前置条件。

## 工程原则

- 模型负责理解、提取、分类和提出建议；可信业务事实应从后端或权威数据源获取。
- 后端负责鉴权、参数校验、业务规则、状态变更和最终结果确认。
- 对缺失信息要追问，对工具失败要有明确的错误处理与兜底流程。
- 工具调用遵循最小权限原则；执行有副作用的操作前应进行必要的验证与确认。
- 将模型输出视为不可信输入，使用 Schema、类型检查和业务校验约束输出。
- 项目成果应可运行、可测试、可解释、可复现；Demo 能运行不等于系统可靠。
