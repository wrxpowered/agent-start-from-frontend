# 学习规则与工程原则

## 学习节奏与进度

- 不规定每次学习必须投入固定时长；按内容难度、连续性和学习效果安排。
- 需要连续思考、编码或调试的任务，优先保障完整性和思路连贯，不为了满足时长而强行中断。
- 短知识点在理解并完成必要验证后即可结束，不为了凑时长增加内容。
- 使用实际完成的学习单元追踪进度，不使用连续日历天数编号。
- 中断后从上次实际进度继续，不因错过日期而自动跳过内容。
- 未达到学习目标或阶段验收标准时，继续补充练习和验证，不因计划日期而提前推进。
- 每个学习单元按需包含：路线定位、概念讲解、实践任务、结果验证和总结；具体深度与时长由内容决定。
- 日常学习聚焦当前阶段。总体路线用于把握方向，不要求一次学习跨越多个阶段。

## 总体学习路线

AI / LLM 基础与结构化交互 → 模型 API 与 TypeScript 后端 → Python 工程基础 → RAG 与检索评估 → Tool Calling 与 Agent → MCP → 生产级 Agent 工程。

详细阶段目标、项目和验收标准以 [stages/](../stages/) 下对应阶段文件为准。

## 工程原则

- 优先采用云端模型/API 与轻量工具，不把本地运行大型模型作为前置条件。
- 先理解底层机制，再引入框架；避免同时学习多个功能重叠的框架。
- 模型负责理解、提取、分类和提出建议；可信业务事实应从后端或权威数据源获取。
- 后端负责鉴权、参数校验、业务规则、状态变更和最终结果确认。
- 对缺失信息要追问，对工具失败要有明确的错误处理与兜底流程。
- 工具调用遵循最小权限原则；执行有副作用的操作前应进行必要的验证与确认。
- 将模型输出视为不可信输入，使用 Schema、类型检查和业务校验约束输出。
- 项目成果应可运行、可测试、可解释、可复现；Demo 能运行不等于系统可靠。
