# 面向初学者的学习方式

这份说明用于指导整个学习项目的讲解深度，不是额外的课程或前置阶段。

## 适合当前起点的教学原则

用户有 Web 前端开发经验，但数学、后端、数据工程和 AI 基础不应被假定为熟练。讲解时从已知经验出发，但对前端以外的概念要明确解释。

### 讲解一个新概念的顺序

1. **先说问题：** 它要解决什么实际问题？没有它会怎样？
2. **再说直觉：** 用生活例子、流程图或前端开发中相似的概念解释。
3. **给一个具体例子：** 使用少量数据，手动走一遍过程。
4. **再介绍术语：** 解释术语的准确含义以及类比不适用的地方。
5. **连接代码：** 从最小可运行例子开始，逐段解释关键逻辑。
6. **确认理解：** 用一个小问题或修改任务检查是否理解，再进入下一概念。

### 数学怎么学

- 不安排“先把高等数学、线性代数、概率论学完再开始 AI”的前置路线。
- Token、上下文、概率和模型生成先从直观例子开始。
- Embedding 和向量检索先理解“把内容变成便于比较的数字表示”，再用小例子解释相似度；只在需要时介绍公式。
- 评估指标先解释它回答什么问题，再用小数据手算一个例子。
- 如果某个数学知识不是当前任务的必要条件，标记为“了解即可”或“以后再学”，不扩展成数学课程。
- 当公式确实必要时，逐个解释符号、输入、输出和实际用途。

### 非前端工程基础怎么学

- HTTP、服务端、数据库、命令行、环境变量、依赖管理、部署和日志等概念第一次出现时都要解释。
- 说明一次请求从哪里发出、经过什么组件、在哪处理、结果如何返回。
- 先做本地或云端的最小可运行例子，再补充生产环境的复杂情况。
- 每个命令说明它做什么、在哪个目录执行，以及成功时应该看到什么。
- 对报错提供可操作的排查顺序，不默认用户能从堆栈信息独立定位问题。
- 后端、安全和数据库知识以当前 Agent 项目需要为准，不扩展成完整后端工程课程。

### 控制每次学习的认知负担

- 一次重点讲清少量新概念，不把一整页术语当作入门讲解。
- 明确区分：现在必须会、现在理解大意即可、以后按需学习。
- 先解释为什么这样设计，再介绍框架的 API。
- 练习要能检查结果；如果答案不对，优先定位理解断点，而不是直接给出更复杂的版本。
- 学习时长随内容和任务完整性调整，不以固定课时为目标。

## 本项目的目标

目标不是降低工程标准，而是把达到工程标准的过程拆成更容易理解和验证的步骤。最终仍要能独立解释设计、编写和调试代码、测试边界条件，并说明系统的限制。
